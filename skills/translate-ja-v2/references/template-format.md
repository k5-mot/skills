# template.dotx 書式仕様

この文書は `skills/translate-ja-v2/examples/template.dotx` の正本仕様である。テンプレートの作成、修正、検証では、以下の要件をすべて満たすこと。

## 1. 基本フォント・色

| 対象        | 英語フォント          | 日本語フォント  | サイズ・書式     |
| --------- | --------------- | -------- | ---------- |
| 見出し       | Arial           | MS Pゴシック | 見出しレベル別    |
| 主題・表紙タイトル | Arial           | MS Pゴシック | タイトル用サイズ   |
| 副題        | Arial           | MS Pゴシック | 副題用サイズ     |
| 表タイトル     | Arial           | MS Pゴシック | タイトル系      |
| 図タイトル     | Arial           | MS Pゴシック | タイトル系      |
| コードタイトル   | Arial           | MS Pゴシック | タイトル系      |
| ヘッダー      | Arial           | MS Pゴシック | ヘッダー用      |
| フッター      | Arial           | MS Pゴシック | フッター用      |
| その他本文     | Times New Roman | MS P明朝   | **10.5pt** |

テンプレートに登録する主要スタイルの確定値は以下とする。

| スタイル | サイズ | 補足 |
| --- | ---: | --- |
| 標準 | 10.5pt | Times New Roman／MS P明朝、黒 |
| 主題 | 28pt | Arial／MS Pゴシック |
| 副題 | 14pt | Arial／MS Pゴシック |
| 表・図タイトル | 10pt | キャプション用スタイル |
| コードタイトル | 10.5pt | 中央揃え |
| ヘッダー・フッター | 9pt | Arial／MS Pゴシック |
| コードブロック・数式ブロック | 10.5pt | 四周を黒い罫線で囲む |

原則として、文字・罫線・表・図タイトル等は**すべて黒**とする。

唯一の例外として、**Note／注意ブロック類は色付き可**とする。表の内罫線を含め、それ以外の罫線には灰色等を使用しない。

---

## 2. ページ設定

用紙サイズは**A4縦（210 × 297 mm）**とする。

用紙余白はWordの「狭い」とし、**上下左右すべて12.7 mm**とする。上下だけを広げるなど、辺ごとに異なる値を設定しない。

ヘッダー・フッターの紙端からの距離は**約10 mm**を基準とする。

ヘッダー・フッターを紙端方向へ押し出して余白を作らない。紙端側の位置は通常位置を維持し、**本文側だけに余白を確保**する。

---

## 3. 見出し

### 見出しスタイル

Wordのスタイルギャラリーに、以下をすべて正式なクイックスタイルとして登録する。

| レベル  |    サイズ | 太字 | イタリック | 配置  |
| ---- | -----: | -- | ----- | --- |
| 見出し1 |   14pt | 太字 | なし    | 左揃え |
| 見出し2 |   12pt | 太字 | なし    | 左揃え |
| 見出し3 |   11pt | 太字 | なし    | 左揃え |
| 見出し4 | 10.5pt | 通常 | なし    | 左揃え |
| 見出し5 | 10.5pt | 通常 | なし    | 左揃え |
| 見出し6 | 10.5pt | 通常 | なし    | 左揃え |

見出しには**イタリックを使用しない**。

### 見出し番号

階層番号は次の形式。

```text
7
7.1
7.1.1
7.1.1.1
7.1.1.1.1
7.1.1.1.1.1
```

番号の前に余計な箇条書き記号を付けない。

### 番号と見出し本文の間隔

最終調整値は以下。

| 見出し    |        見出し本文の開始位置 |
| ------ | ----------------: |
| 見出し1～3 |  左端から **12.7 mm** |
| 見出し4～6 | 左端から **約22.9 mm** |

つまり、見出し1～3は比較的狭く、見出し4～6は長い番号を考慮して少し広くする。

各グループ内では見出し本文の左端を完全に揃える。

---

## 4. 目次

タイトルは英語の `Table of Contents` ではなく、**「目次」**とする。

「目次」自体には章番号を付けない。

本冊の見出し1～6を目次対象とする。

TOCフィールドは、見出し1～6を対象とする次の設定を基準とする。

```text
TOC \o "1-6" \h \z \u
```

**付録以降は目次に含めない。**

WordがTOCフィールド内部に保持する現在の表示結果は使用してよい。ただし、TOCフィールドの終了後に、キャッシュされた古い階層リストや、

```text
1 Document Control
1.1 Lists
1.1.1 Table
...
```

のような重複テキストを残さない。

TOCは文書内部のフィールドとして使用してよいが、Word起動時に外部参照警告を発生させないこと。

---

## 5. 本冊・付録

文書は**本冊＋付録**で構成する。

付録Aの先頭には、

**「付録A」**

を独立して配置し、このラベルだけは**中央揃え**とする。

付録内の見出しは**左揃え**とする。

付録用見出しは本冊とは別スタイルとして管理してよいが、**TOCには含めない**。

付録用スタイルの基準値は以下とする。

| スタイル | サイズ | 配置 | TOC対象 |
| --- | ---: | --- | --- |
| 付録ラベル | 18pt | 中央揃え | 対象外 |
| 付録見出し1 | 14pt | 左揃え | 対象外 |
| 付録見出し2 | 12pt | 左揃え | 対象外 |

付録用スタイルにはアウトラインレベル9相当を設定し、本冊の見出しスタイルを基にしていてもTOCへ混入しないようにする。

---

## 6. ページ番号

総ページ数表示は使用しない。

`1/20` や `Page 1 of 20` のような形式は禁止。

本冊は、

```text
<章番号>-<章内ページ番号>
```

とする。

例：

```text
3-1
3-2
3-3
```

章が変わったらページ番号を1から再開する。

付録Aは、

```text
A-1
A-2
A-3
```

とする。

---

## 7. ヘッダー

ヘッダーは3領域構成。

| 領域 | 配置   |
| -- | ---- |
| 左  | 左揃え  |
| 中央 | 中央揃え |
| 右  | 右揃え  |

例えば、

```text
システム 基本設計書          （中央情報）          SYS-DS-001
```

のような配置とする。

構造は、

```text
ヘッダー内容
────────────── 罫線

空行
本文
```

とする。

つまり、**ヘッダー → 罫線 → 空行**の順にし、空行を本文とのクリアランスとして使用する。

---

## 8. フッター

フッターも3領域構成。

| 領域 | 配置   |
| -- | ---- |
| 左  | 左揃え  |
| 中央 | 中央揃え |
| 右  | 右揃え  |

例：

```text
社外秘 / ○○株式会社          3-1          2026/08/21最終更新
```

日付は必ず、

```text
yyyy/MM/dd最終更新
```

形式。

構造はヘッダーと逆に、

```text
本文
空行

────────────── 罫線
フッター内容
```

とし、**本文側だけにクリアランスを確保**する。

---

## 9. 箇条書き・番号付きリスト

Wordで実際に箇条書き記号・番号が表示される、正式なWord番号定義を使用する。

箇条書き例：

```text
• 階層1
  • 階層2
    • 階層3
```

番号付き例：

```text
1. 項目1
2. 項目2
   2.1 子項目
```

階層1から階層2へのインデント差は大きく取りすぎず、**約3.2 mm程度＝「・」1文字分程度**とする。

階層3も同程度の増分とする。

LibreOfficeだけでなく、**Microsoft Wordで箇条書き記号・番号が確実に表示されること**を確認する。

---

## 10. 図

テンプレート内に図のサンプルを置く。

300×200程度のプレースホルダーでよい。

ただし、

```text
https://placehold.jp/300x200.png
```

をリンクとして参照するのではなく、**画像そのものをDOTX内に埋め込む**。

図ラベルは英語の `Figure` ではなく、

**「図」**

とする。

例：

```text
図 1　システム構成例
```

---

## 11. 表

表ラベルは `Table` ではなく、

**「表」**

とする。

複数ページにまたがる表では、

* ヘッダー行を次ページでも繰り返す
* 可能な限り行途中でページ分割しない
* ページ上端のヘッダー罫線と表罫線が接触しない
* ページ下端のフッター罫線とも接触しない

ようにする。

この余白はページ余白そのものを広げるのではなく、**ヘッダー／フッター内の本文側空行で確保する**。

テンプレートには、少なくとも次の表サンプルを含める。

* 表紙の文書情報表
* 文書管理・改訂履歴表
* 通常のデータ表
* 複数ページへの分割確認用の長い表

データ表と長い表では、先頭行を繰り返し見出し行として設定し、各行には可能な限り行途中で改ページしない設定を適用する。表の外枠だけでなく内罫線も黒にする。

---

## 12. コード

ラベルは `Code` ではなく、

**「コード」**

とする。

例：

```text
コード 1　ソースコード例
```

コードタイトルは**中央揃え**。

コード本文は本文と区別できるように、**黒い罫線で四周を囲む**。

さらに「コードブロック」を正式なWordスタイルとして登録し、**スタイルギャラリーに表示**する。

コード本文を単にインデントしただけの表現にはしない。

コード本文の基準サイズは**10.5pt**とする。

### インラインコード

本文および表セル内の短いコードには、段落用のコードブロックとは別に、**インラインコード用の文字スタイル**を使用する。

インラインコードを含むサンプルを本文と表セルの両方に配置し、通常本文へ変換された場合でも用途を判別できるようにする。

---

## 13. 数式

数式も本文と明確に区切る。

**数式ブロックを黒い罫線で囲む。**

「数式ブロック」をWordスタイルとして登録する。

---

## 14. Note／注意ブロック

以下の全種類をDOTX内にサンプルとして掲載する。

| 種類        | 日本語例 |
| --------- | ---- |
| NOTE      | 注記   |
| TIP       | ヒント  |
| IMPORTANT | 重要   |
| WARNING   | 警告   |
| CAUTION   | 注意   |

これらだけは全黒ルールの例外として、**識別しやすい色付けを許可**する。

文字色はすべて黒のままとし、背景色と左罫線のみを次の配色にする。

| 種類 | 背景色 | 左罫線色 |
| --- | --- | --- |
| NOTE | `#DDF4FF` | `#0969DA` |
| TIP | `#DAFBE1` | `#1A7F37` |
| IMPORTANT | `#F3E8FF` | `#8250DF` |
| WARNING | `#FFF8C5` | `#9A6700` |
| CAUTION | `#FFEBE9` | `#CF222E` |

---

## 15. 表紙

通常本文とは明確に異なる、正式な「表紙らしい」レイアウトとする。

構成例：

```text
システム名

基本設計書
Basic Design Specification

────────────────

Document ID
Revision
Status
Date
Author

会社名
```

タイトル階層を明確にし、適切な余白と区切り線を設ける。

文書情報は整然とした表形式にしてよい。

文書ID、文書種別、英語副題は、表紙・ヘッダー・文書管理表の間で一致させる。例えば表紙を「基本設計書」とする場合、ヘッダーだけを「詳細設計書」とするなどの不整合を残さない。

表紙では通常本文用のヘッダーとフッターを表示しない。表紙の次のセクションから本冊用のヘッダー、フッターおよび章内ページ番号を開始する。

表紙についてもNoteブロック以外は**黒のみ**を使用する。

---

## 16. 文書内の補助要素

### 脚注

テンプレートには、Wordの正式な脚注機能を使用した脚注サンプルを1件以上含める。脚注番号を本文へ直接入力しただけの表現にはしない。

### 定義リスト

用語と説明を区別できる、定義語用スタイルと定義本文用スタイルを登録し、定義リストのサンプルを含める。

### リンクとブックマーク

章番号参照や目次の移動先には、文書内ブックマークや内部リンクを使用してよい。外部ファイルへのリンクは含めない。

---

## 17. 外部ファイル参照の禁止

これは特に重要。

DOTXには**他ファイルを参照するフィールド・リンク・リレーションを一切含めない**。

OOXMLレベルで以下を確認する。

```text
TargetMode="External" = 0件
```

以下の外部参照系フィールドも含めない。

```text
INCLUDETEXT
INCLUDEPICTURE
LINK
DDE
DATABASE
外部HYPERLINK
```

Web上の画像もリンクとして保持せず、必ず埋め込む。

Wordを開いた際に、

> この文書には他のファイルを参照するフィールドが含まれています。

という警告を出さないようにする。

そのため、

* 外部relationshipを残さない
* `updateFields` の自動更新指定を残さない
* TOC等に不要な `dirty` フラグを残さない

ことも確認する。

内部完結するTOC、PAGE等のフィールドは使用可能。

---

## 18. 納品前チェック

最終DOTXでは、少なくとも次を確認すること。

1. Microsoft Wordで開いて外部参照警告が出ない
2. 見出し1～6がスタイルギャラリーに存在する
3. コードブロック・数式ブロックがスタイルとして存在する
4. 見出し番号位置と本文位置が指定どおり
5. 箇条書き・番号付きリストの記号がWordで表示される
6. 目次タイトルが「目次」
7. 付録が目次に入らない
8. ヘッダー／フッターと本文・表の間に余白がある
9. ページ番号が `<章>-<ページ>` / `A-<ページ>` 形式
10. 図が外部リンクではなく埋め込み
11. Note系5種類のサンプルが存在する
12. 全ページをレンダリングして崩れ・重なりを確認する
13. A4縦で上下左右の余白がすべて12.7 mmになっている
14. 表紙・ヘッダー・文書管理表の文書種別と文書IDが一致する
15. 表紙に通常本文用のヘッダーとフッターが表示されない
16. 表の内罫線を含め、Note系以外の文字と罫線が黒である
17. インラインコード、脚注、定義リストのサンプルが存在する
18. 長い表で見出し行が繰り返され、行途中の分割が抑止される

このチェックをすべて満たしたDOTXだけを、翻訳パイプラインの標準テンプレートとして扱う。
