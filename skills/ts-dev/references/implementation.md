# 実装工程

TypeScriptフロントエンドを実装・修正するときはこの規約を使う。

## JSDoc/TSDocとコメント

- 関数・コンポーネント・公開ユーティリティにはJSDoc/TSDocを書く。
- JSDoc/TSDocには目的、引数、戻り値を書く。
- 例外や副作用がある場合は `@throws` や説明文で追記する。
- コメントを書く場合は日本語で、コードの逐語説明ではなく理由や注意点を書く。

## UI実装

- UI/E2Eテストが必要な挙動は、実装時点でPlaywrightで観測できる状態にする。
- UIライブラリやデザインシステムの既存規約を優先する。
- public utilityの振る舞いを変えた場合は `docs/` に利用方法や変更点を残す。
